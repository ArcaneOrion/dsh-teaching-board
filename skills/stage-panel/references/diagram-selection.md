# 展现方式选型：信息类型 → 图型

生成任何 panel 之前先完成选型。本文件是「选型」的唯一家：关系类型→图型的完整目录、Shannon 依据、声明格式。选型之后的 HTML 组织方式见 `html-patterns.md`，视觉语言见 `visual-style.md`。

## 0. 一次三问

1. **核心关系是哪一种？**（§2 结构关系 8 种 / §3 数据图表族）——决定图型。
2. **读者在哪个阶段？** 读（第一眼建骨架）→ 看（第二遍看关系）→ 玩（深挖探索）——决定交互密度。
3. **纯文本＋表格能否说清？** 能 → 不生成 panel。文本是一等公民，panel 是放大器不是入口。

## 1. Shannon 三把尺子

展现形式的取舍本质是信息传输的取舍。三把尺子：

- **信息密度（熵）**：每元素承载的不可预测性。线性文本每字符熵最高、但需逐字解码；结构图把「关系」编码进位置，每元素熵降低、辨识提速。
- **冗余**：同一信息重复编码的次数。好的展示有意冗余——同一关系用「位置＋颜色＋标签」至少编码两遍，帮读者抗噪；装饰性动画不承载任何区分度，是噪声不是冗余。
- **信道带宽**：读者单次能接收的量有限（工作记忆约 4 组块）。一屏活跃元素超过约 9 个就必须分组、分页或分层展开；交互的本质是**按需分配带宽**——默认只给骨架，点击才注入细节。

推导出的四条规则：

1. 内容熵高（新颖叙述、不可预测的推理多）→ 以线性文本为主，图只给骨架。
2. 关系可预测（层级/流程/状态）→ 图的压缩效率最高，优先用图。
3. 一屏超过约 9 个活跃元素 → 分组或分层展开，不要硬塞。
4. 想强调一个关系 → 给它至少两种编码（位置＋颜色/标签）；想删一个元素 → 先问它承载了什么区分度。

## 2. 结构关系 8 种 → 图型

| # | 关系 | 选它的问句 | 图型 | 何时不用 |
|---|------|-----------|------|---------|
| 1 | 包含/层级 | 谁套着谁？ | 树状图（思维导图=放射变体、旭日图=径向变体） | 只有一层 → 改列表 |
| 2 | 步骤顺序 | 先做什么后做什么？ | 流程图；无分支时用时间线 | ≤3 步且无分支 → 编号列表 |
| 3 | 参与者消息 | 多方之间谁发给谁、按什么顺序？ | 时序图/泳道图 | 只有两方一问一答 → 两行对照 |
| 4 | 静态连接 | 谁跟谁有联系（无层级）？ | 网络图/组件框图/依赖 DAG | 边数会变毛球（>15 条）→ 矩阵表 |
| 5 | 状态变迁 | 它待在哪，什么事件让它换地方？ | 状态机图 | 状态 >7 个 → 先分组 |
| 6 | 数据形状 | 实体之间是 1:N 还是 N:M？ | ER 图 | 设计存储/日志格式前画，之后当参考 |
| 7 | 依赖方向 | 谁依赖谁、只能向下调？ | 分层架构图 | 依赖双向或无分层 → 改网络图 |
| 8 | 交叉对照 | 两组维度要交叉看？ | 矩阵表 | 关系只有一组维度 → 改清单 |

树、时序、状态机、分层的最小骨架：

```text
A                      你      循环      模型        [空闲] --输入--> [思考]         ┌─────────┐
├─ B                   │──提问──→│         │           [思考] --工具调用--> [执行]      │ 装配层  │
│  └─ D                │         │──请求──→│           [执行] --完成--> [空闲]         ├─────────┤
└─ C                   │         │←─分片───│                                           │ 服务层  │
                                                                                   ├─────────┤
                                                                                   │ 适配层  │
                                                                                   └─────────┘
```

## 3. 数据图表族（数值型信息）

选型问句：**这些数字在回答什么问题？**

| 数字在回答 | 图型 | 防坑 |
|-----------|------|------|
| 类别之间比大小 | 柱状图 | 类别名太长转条形图 |
| 随时间怎么变 | 折线图 | 别截断 y 轴夸大变化 |
| 整体由什么构成 | 饼/环/堆叠柱 | 块 >5 改条形 |
| 两个量是否相关 | 散点图 | 相关≠因果，把第三变量标出来 |
| 数值怎么分布 | 直方图/箱线图 | 别拿均值冒充分布 |
| 总量怎么分流 | 桑基图 | 只用于守恒型流动 |

## 4. 组合与递进

- 一个 panel 常是 2-3 种图组合，但**每层必须能独立回答一个不同的问题**——不是同一份数据换花样画三遍。
- 默认递进：读层给结论句 → 看层给主图 → 玩层做交互放大器（点开细节/筛选/对照）。
- 跨图一致性：同一实体在不同图里同名同色，读者不用重新对表。

## 5. 声明格式（与 SKILL.md 标准流程挂钩）

生成 panel 前，在 CLI 用 1-3 行声明选型，让用户可检查、可纠正：

```text
选型：核心关系=包含层级 → 树；次关系=依赖方向 → 分层图
交互：第二步放大器（点节点看上下文），首屏纯读
```

- 核心关系选不出图型 → 说明需求还没长成，先回终端问用户。
- 「不生成 panel：文本足够」也是合法的选型结论。
